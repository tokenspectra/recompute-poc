# recompute-poc v1: results of the first run (2026-10-25)

Setup: two Nebius `gpu-h100-sxm` VMs in eu-north1 (one H100 each), vLLM v0.32.0 pinned by image
digest, Model Runner V2, `--generation-config vllm`, Qwen/Qwen3-4B. VM-A served traffic through the
API Tap gateway; its Workunits were scored on VM-B with teacher-forced prefill + our numpy replay of
the V2 Gumbel draw (fast path). Raw data: `data/run-20261025/` (gitignored, ~350 MB).

## Detection vs window size

second half is held out for the false-positive rate. Windows are consecutive output tokens (they can
span Workunits).

|---|---|---|---|---|---|
| 16 | 6144 / 6144 / 6144 | 0.3125 | 0.000 | 0.701 | 0.959 |
| 32 | 3072 / 3072 / 3072 | 0.1645 | 0.000 | 0.881 | 0.981 |
| 64 | 1536 / 1536 / 1536 | 0.0839 | 0.001 | 0.993 | 1.000 |
| 128 | 768 / 768 / 768 | 0.0552 | 0.000 | 1.000 | 1.000 |

Reading: with these thresholds, about 64 tokens separate this swap from honest traffic with roughly
one false positive per thousand windows; 128 tokens separate it perfectly in this sample.

### Stratified re-run (same data, no new GPU time)

`scripts/stratified_eval.py`: within each of the 12 load cells, Workunits alternate between
calibration and holdout, so both halves cover every concurrency, stream mode and temperature.

| window (tokens) | cal / holdout / control windows | tau | FPR (honest holdout) | TPR (control) | AUC |
|---|---|---|---|---|---|
| 16 | 6144 / 6144 / 6144 | 0.3125 | 0.000 | 0.701 | 0.959 |
| 32 | 3072 / 3072 / 3072 | 0.1591 | 0.002 | 0.883 | 0.981 |
| 64 | 1536 / 1536 / 1536 | 0.0820 | 0.003 | 0.993 | 1.000 |
| 128 | 768 / 768 / 768 | 0.0509 | 0.000 | 1.000 | 1.000 |

| 512 | 192 / 192 / 192 | 0.0208 | 0.005 | 1.000 | 1.000 |
| 1024 | 96 / 96 / 96 | 0.0113 | 0.010 | 1.000 | 1.000 |

- Detection is unchanged. FPR at 512 and 1024 tokens is one holdout window each (1/192, 1/96), so it
  is at the resolution limit and is not evidence of a trend.
- Mean honest margin per load cell is flat across concurrency (T=0: 0.0007 to 0.0009; T=0.6: 0.0032
  to 0.0057), so batch size does not visibly widen the honest band in this run. T=0.6 is about five
  times wider than T=0, so tau per temperature is worth considering for TS-16.
- At T=0.6 the maximum per-token margin is 5.0 in every cell, i.e. the `delta_max` clip: some honest
  tokens fall outside the replayed top-k/top-p set (0.03 % of tokens).

## What this does and does not show

- Shows: the API Tap captures and strips correctly (incl. SSE); a verifier on a second GPU reproduces
  VM-A's sampling with a narrow honest band; a swap to the smaller sibling model is caught quickly.
- The control is the easy end of the range. Same-size Instruct, FP8 or AWQ swaps are untested, and
  would need many more tokens.
- One run, one model, one vLLM version, one GPU SKU, one region. FPR resolution is 1 / holdout windows
  (0.000 means none in that sample, not zero probability). No confidence intervals.
- `rpoc evaluate` splits honest tokens by scoring order, which follows the load cells, so its halves
  differ in concurrency. The stratified re-run below removes that confound and gives the same picture.
- The operator is cooperative here: the gateway records are claims, as accepted for v1.
- The two VMs may sit on the same host or rack; we did not check, so "two physical GPUs" means two
  separate VMs with one H100 each.
- Both gateway honest/control runs used the declared manifest. VM-A's manifest was hashed with
  `v2_runner_logged=false` because of a log-matching bug in `serve.sh` (fixed in the repo); with the
  flag corrected both VMs hash to `c415416d9e98062e`. The daemon accepted both ids.
- Thresholds are provisional until TS-16 closes with the team.
